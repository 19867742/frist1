# FlowAtlas 产品与技术设计文档

## 1. 设计目标

| 维度 | 目标 | 落地方式 |
| --- | --- | --- |
| 可用性 | 华为 nova9（6.57", 2340×1080, HarmonyOS）上单手可操作 | 底栏 5 键 + 中央 FAB；点击区 ≥ 38px；安全区适配；底部弹层而非居中弹窗 |
| 界面风格 | **以图为主、颜色丰富、可点入查看** | 卡头大数字 + 环形/柱状/折线/热力图/排行榜；分类色板 14 色；emoji 分类图标；点任意卡片进入明细 |
| 数据来源 | 微信 / 支付宝账单文件导入，自动识别规划整理 | 自研解析引擎（表头定位 + 字段映射 + 去重 + 分类三层） |
| 隐私 | 不商业化、不联网 | 纯前端 + localStorage + 可选 AES-256-GCM |
| 交付 | 安卓手机即装即用 | PWA（Service Worker 离线缓存，可添加到桌面） |

## 2. 信息架构

```
首页       净资产 / 本月收支 / 预算环 / 快捷宫格 / 提醒 / 洞察 / 预算快览 / 最近流水
流水       搜索 + 方向筛选 + 高级筛选 → 按日分组 → 交易详情（改分类/拆分/排除/删除）
导入 ➕    来源选择 → 账户选择 → 上传解析 → 预览确认 → 去重入库；截图 OCR；手动补录
规划       预算 | 目标 | 债务 | 订阅（四段式切换）
报告       月份选择 → 概览 → 洞察 → 支出构成 → 趋势 → 热力图 → Top商户 → 异常 → 预算 → 资产负债 → 导出
我的       资料、账户与数据源、规则与学习、备份恢复、隐私加密、偏好、关于
```

## 3. 数据模型

```js
Transaction {
  id, time, amount(正数), direction: expense|income|transfer,
  accountId, transferTo?, merchant, item, rawCategory, payMethod,
  status: success|refunded|closed|other, orderNo, merchantNo, note,
  source: wechat|alipay|bank|manual, category, sub, tags[],
  excluded(不计入收支), auto:{source,confidence}, mediaId?(OCR凭证)
}
Account   { id, type: wechat|alipay|bank|cash|other, name, icon, color, initial, holder, include }
Budget    { name, amount, categories[], icon, color, period }
Goal      { name, targetAmount, saved, deadline, contributions[] }
Debt      { name, type, principal, balance, apr, minPayment, dueDay, payments[] }
Sub       { name, amount, cycle, nextDate, lastDate, category, status, key, autoDetected }
Correction{ key(商户归并键), category, sub, n }   // 用户纠正记忆
```

**余额口径**：`余额 = 初始余额 + 收入 − 支出 ± 转账`（转账进出双向记账，不计入收支统计）。
**净资产** = Σ 计入账户余额 − Σ 未结清债务余额。

## 4. 解析引擎

### 4.1 表头定位算法
1. 逐行扫描前 40 行，对每行打分：命中已知表头词（交易时间/金额/收·支/交易对方…）+2，命中 13 类字段别名各 +1；
2. 取最高分行；要求必须能定位 **时间** 与 **金额** 且总分 ≥ 6，否则判定失败并给出可读错误；
3. 微信账单的 11 行说明、支付宝的 4 行说明、银行导出的标题行、空行、汇总行均被自然跳过。

### 4.2 编码与格式
- `TextDecoder('utf-8', {fatal:true})` 先行试探，失败回退 **GBK**（微信/支付宝导出常见）；
- `.xlsx`：手写 ZIP 中央目录解析 + 浏览器原生 `DecompressionStream('deflate-raw')` 解压 → 正则解析 `sharedStrings.xml` / `sheet*.xml`，**零第三方依赖**；
- CSV：状态机解析，支持引号包裹、字段内逗号/换行、`""` 转义，分隔符在 `,\\t;|` 中自动嗅探。

### 4.3 去重策略（两道）
1. **硬键**：`orderNo` 相同 → 必为同笔（跨文件导入同样生效）；
2. **软指纹**：`账户 + 分钟级时间 + 金额 + 方向 + 商户归并键` 全等 → 视为重复（应对无单号的银行流水）。

### 4.4 方向与状态
「不计收支 / 中性交易」**最先判定**（否则会被"支"字误伤），再结合交易类型决定是转账还是收支；`交易关闭/失败` 直接跳过，`已退款` 打标并尝试与 90 天内同商户同额支出关联。

## 5. 分类引擎（三层）

```
用户纠正记忆  ──未命中──▶  关键词规则（商户名优先，最长词胜出）  ──未命中──▶  朴素贝叶斯
   confidence 0.99               confidence 0.90                      confidence 由 softmax 得出
        │                              │                                     │
        └────────────── 命中即返回分类 + 子分类 + 来源标签 ◀──────────────────┘
                                    │ 全部未命中
                                    ▼
                          兜底「其他 / 其他收入」并标记「待确认」
```

- **分词**：中文 bigram + 拉丁词，含停用词表（有限公司/科技/网络…）；
- **训练数据**：用户确认样本（memory/user）优先；不足 12 条时掺入规则命中样本做冷启动，随纠正增多自然转向个性化；
- **商户归并**：括号、公司后缀、支付通道词清洗 + 别名表（KFC→肯德基、美团平台商户→美团、Apple/iCloud→Apple）；
- **周期性识别**：同一商户支出按时间排序，先折叠同周期重复扣款（≤10 天），再按间隔中位数与变异系数判定 周/月/季/年，金额需稳定；
- **异常检测**：分类内 MAD 离群（阈值 = max(中位数+5×MAD, 4×中位数, 100)）、同商户同额 24h 内重复、凌晨大额。

## 6. 月度报告与分享图

报告对象 `report.build(ym)` 输出：收支汇总、环比、分类聚合（含子分类）、Top 商户、每日序列与热力图数据、近 6 月趋势、预算执行（含**进度偏差 pace** 与日均可用额度）、异常清单、资产负债、订阅月均、债务月供、目标进度、以及**自动文字洞察**（最多 9 条：环比、储蓄率、占比最高分类、增速最快分类、超支预警、订阅成本、异常笔数、Top 商户、净资产）。

分享长图由 `report.shareCard()` 用 Canvas 1080×1900 直接绘制（渐变背景 + 光晕 + 环形图 + 折线 + 排行 + 预算条），`toDataURL('image/png')` 下载，尺寸与内容为朋友圈/微信群浏览优化。

## 7. 视觉规范

- **主色**：`#4D96FF → #8E7CFF → #F473B9`（蓝紫粉渐变，用于主按钮/净资产卡/FAB）
- **语义色**：支出 `#FF6B6B`，收入 `#22C55E`，警告 `#F59E0B`，危险 `#EF4444`
- **分类色板**（14 色）：`#FF6B6B #4D96FF #F473B9 #FFB020 #2ED3B7 #8E7CFF #FF8A3D #3EC1D3 #22C55E #EAB308 #EF4444 #6C5CE7 #14B8A6 #A0C15A`
- **深浅主题**：跟随系统 / 手动切换，深色为深蓝夜景 + 彩色光晕
- **图标**：分类与账户用彩色 emoji（零资源、跨端一致、色彩丰富），界面操作用 24 个手写 SVG 单色线性图标

## 8. 兼容性与性能

- 仅依赖 Chrome 86+ 已支持的能力：`TextDecoder`、`DecompressionStream`、`WebCrypto.subtle`、`Canvas2D`、Service Worker；无构建、无 npm 依赖、无 CDN；
- 全部脚本为 **传统 script**（非 ES Module），因此 `file://` 直接打开也能运行；
- 146 笔示例数据下：首页渲染 ~150 节点、流水页 ~1400 节点、报告页 ~230 节点；分类/报表均为一次性 O(n) 遍历，万笔量级仍在毫秒级；
- 数据变更 500ms 防抖落盘；页面隐藏（切后台）时强制 flush，避免丢数据。

## 10. 插图系统

界面遵循「以图为主、颜色丰富、可点入查看」，所有视觉资产由脚本生成，无外部素材、无版权风险。

**生成管线**（`tools/make_illustrations.py`）

```
图元规格（每个插图 3~6 个图元：圆角矩形 / 圆 / 描边圆 / 圆弧 / 折线 / 多边形）
        ├─▶ SVG 渲染器 ──▶ assets/illust-<name>.svg    （矢量源文件，可再编辑）
        │                └▶ js/illustrations.js        （内联 data URI，运行时零请求）
        └─▶ PIL 渲染器 ──▶ assets/png/<name>.png       （位图，供合成与二次使用）
                          └▶ docs/illustrations-sheet.png（总览图）
```

同一份规格双渲染器输出，保证 SVG 与 PNG 完全一致；改配色或造型只需改图元列表后重跑。

**覆盖范围**：18 个功能模块 + 23 个收支分类 + 6 个账户来源/警示 = **47 张**。
分类插图名与数据里的分类 id **一一对应**，因此 `UI.catIllust(t.category)` 可直接取图。

**运行时接入**
- `UI.illust(name, size)` / `UI.catIllust(catId, size)`：返回带 data URI 的 `<img>`，不产生网络请求，`file://` 下同样可用；
- 用在：快捷宫格、区块标题、交易行图标、交易详情头图、分类选择器、空状态、导入拖拽区、订阅检测行、隐私/备份卡头；
- 列表页图标由 emoji 换成插图后视觉一致性明显提升（同一分类在首页、明细、报告、详情里都是同一张图）；
- **自定义封面**：`settings.coverId` 指向媒体库中的压缩照片（1080px / JPEG 0.74），作为净资产卡背景并叠加渐变遮罩保证文字可读，可一键恢复默认插画。

## 11. 安卓外壳（APK）架构

网页端本身是 PWA，但 HarmonyOS 浏览器没有真正的安装包与后台调度能力，因此提供一个**极薄的安卓壳**把同一份代码装成 APK。

| 关注点 | 方案 | 说明 |
| --- | --- | --- |
| 安全上下文 | `WebViewAssetLoader` + 虚拟域名 `https://appassets.androidplatform.net/assets/` | localStorage、WebCrypto（PBKDF2+AES-GCM）、Service Worker 全部可用，这是 `file://` 方案做不到的 |
| 完全离线 | `shouldInterceptRequest` 拦截一切非本地 URL 返回 403，且 `cleartextTrafficPermitted=false` | 代码层面拒绝网络，不只是「没写请求」 |
| 选账单文件 | `WebChromeClient.onShowFileChooser` → `ACTION_GET_CONTENT`（支持多选） | 走系统文件选择器，无需存储权限 |
| 导出图片/备份 | `@JavascriptInterface FlowAtlasNative.saveFile(name, base64, mime)` → MediaStore | 写到「下载/FlowAtlas/」，Android 10+ 免权限；网页端 `U.download()` 自动检测原生桥并切换通道 |
| 返回键 | `onBackPressed`：网页可后退则后退 | 与浏览器行为一致 |
| 构建 | Gradle 8.7 + AGP 8.5.2，minSdk 29 / targetSdk 34 | 不依赖 Capacitor / Cordova，无 npm 依赖 |
| 云端出包 | `.github/workflows/build-apk.yml` | 本机无需 Android SDK，GitHub 免费构建并上传 Artifact |
| 同步网页资源 | `android-app/sync-web.js`（Node，不受 PowerShell 执行策略限制） | 把 `finance-app/` 拷进 `assets/www/`，21 个文件约 340 KB |

## 12. 后续路线（若要媲美甚至超越主流记账 App）

1. **系统级通知**：安卓壳已具备 WebView 与桥接基础，接下来接 WorkManager 定时提醒与前台通知；
2. **截图 OCR 内置**：随包附带量化后的中文识别模型，实现"截图即入账"；
3. **多币种与汇率**：账本级汇率表 + 手动/离线汇率快照；
4. **账单自动获取**：安卓通知监听（需原生权限）自动解析支付通知，做到零手动导入；
5. **多账本与共享**：家庭账本（本地加密导出 + 二维码配对交换，仍不经过服务器）；
6. **预测模型**：基于历史月度收支的 Holt-Winters 季节分解，输出下月现金流区间；
7. **对账自动化**：银行卡流水与微信/支付宝账单三向勾兑，自动发现漏记。
